# UI 与主要流程

## 主窗口流程

`app/ui/main_window.py` 组合数据、布局、操作和实时站点混入类，负责启动以下工作流：

1. 从设置恢复账号、群组选中状态、站点和代理配置。
2. 通过 `AccountResolver` 解析聊天数据源，加载群组和消息。
3. 根据站点的下一期、时间窗口、群组与屏蔽规则构建统计结果。
4. 展示图表、原始消息、机器人汇总校验和导出入口。

## 自动下注流程

`app/ui/auto_bet_panel.py` 提供目标群组、推荐玩法、赔率、策略、服务器托管的 AI 策略参数、历史概率分析、实战统计和运行日志。历史概率区复用当前站点的“历史期数”缓存，显示 13/14 以及小、单、大、双和四种复合玩法的频率；历史不足时显示实际样本量。

1. 使用当前选中站点的 `next_period` 作为下注目标期。
2. 刷新站点历史开奖记录并按目标期过滤数据。
3. 压三门从小单、大双、小双、大单中排除概率最低的一门；只要剩余三门任意一门达到最低置信度，便向每个目标群组同时发送三门指令。13/14 仅用于展示，不参与三门决策。
3. 根据策略与可选玩法生成、确认或跳过建议。
4. 对每个站点、期号和群组组合执行去重发送。
5. 在开奖结果可用后结算，并更新盈亏、连中连输、倍投档位与 AI 统计。

运行日志默认筛选“下注与结算”。日志 API 以带 `+00:00` 的 UTC 时间传输；面板显示和时间范围筛选统一使用北京时间（`Asia/Shanghai`）。自动下注策略保存时同步群组 ID 到群组名的快照，因此策略、AI、发送、过期和结算日志统一以前缀 `【群组名】【站点 期号】` 显示；旧策略在桌面刷新本地群组列表后自动补齐该快照。sender 按用户、群组、站点和目标下一期合并同轮订单，使用 `【群组名】【站点 期号】WSS 已发送下注：【下注玩法 玩法金额、玩法金额...】` 格式展示发送结果，不再为同一群组的每个玩法分别生成一条运行日志。开奖结果入库后，服务器按用户、站点和期号生成一条幂等汇总结算日志，展示开奖结果、和值、总投入、总返还、净收益和盈亏。分类筛选可切换到用户操作、系统、第三方和异常；全局服务事件已脱敏，用户事件继续按账号隔离。下注期号始终取服务端当前源返回的 `next_period`，`current_period` 仅用于展示已开奖期号。

## 配置与帮助

- 代理设置由 `app/ui/proxy_settings_dialog.py` 管理；开奖和历史记录由 FastAPI/worker 在服务器网络中访问，不再使用客户端代理直连第三方源。
- 左侧的“线路选择”“账号与数据源”“屏蔽名单”“自动下注”是互斥展开的一级手风琴，默认展开线路选择。折叠只隐藏模块内容，不会重建控件或丢失选择、输入、运行状态及日志分页位置。
- 自动下注策略由服务器统一托管；客户端不保存或直接调用 AI API Key。
- 当前期开奖由 FastAPI 中转。四站使用独立响应适配器；某条线路短暂返回 503 时，界面保留该线路的上次数据、明确标记为暂不可用，并在后续刷新周期重试；其他线路照常加载。
- 当前界面字段和行为以 `app/ui/` 实现与自动化测试为准。
