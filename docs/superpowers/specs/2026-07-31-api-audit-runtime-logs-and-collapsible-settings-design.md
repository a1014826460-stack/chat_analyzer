# API 审计、运行日志与折叠配置设计

## 目标

完成对桌面客户端、FastAPI 服务、worker 和运维诊断脚本的对外 API 审计；除腾讯聊天/WSS 外，所有业务及第三方网络访问必须由 FastAPI 服务端中转。将自动下注面板的“运行日志”升级为服务端聚合、可检索、可分页的运行日志视图，并将“线路选择”“账号与数据源”“屏蔽名单”“自动下注”四个一级模块改为保持状态的折叠分组。

## 范围与边界

- 包含 HTTP REST、WebSocket/WSS、后台 worker 的第三方 HTTP 请求、桌面应用直连请求，以及 `tools/diagnostics` 内可执行网络探针。
- 腾讯聊天的 REST/WSS 发送与接收是唯一允许的客户端直连例外；它必须在接口审计清单中以 `EXCEPTION-TENCENT-IM` 标识，记录用途、调用位置、所用本地会话凭据及不经过 FastAPI 的理由。
- 本地 SQLite 聊天数据库读取不是网络 API，不迁移；但其导出的数据不得绕过服务端写入业务资源。
- 日志视图只扩展 `AutoBetPanel`，不新增主窗口日志页面。
- 发布更新、开奖当前期与历史、AI、服务器业务 API 和任何后续第三方 HTTP 调用都必须由客户端调用 FastAPI，且不能保留可在生产路径触发的直连兜底。

## 架构

### 接口集中与审计

维护 `docs/api-interface-inventory.md` 作为受版本控制的完整接口清单。它按入口类型列出每个路由、客户端请求、worker 出站请求、诊断工具入口和 Tencent IM 例外，且每条至少包含：标识、协议/方法、入口位置、完整调用链、认证与授权、输入校验、敏感数据、是否必须中转、最终状态及验收测试。

服务端新增受 JWT 保护的只读资源，以覆盖客户端既有业务直连：当前期开奖、历史开奖和受签名清单保护的更新元数据/包下载。worker 是唯一可访问相应第三方开奖和发布源的组件；它写入服务端存储，路由只读取规范化结果。客户端删除或隔离 `fetch_date`、`history_records`、`ai_bet_client`、`update_service` 的生产网络路径，改由 `ServerApiClient` 调用对应的 `/v1/*` 资源。Tencent IM 发送器仍可在客户端直连，但不承担开奖、AI、更新或业务 API 请求。

API 路由均使用 Pydantic/Query 字段边界校验，并使用 `current_user_id` 或管理员依赖保护；`/health/live` 作为负载均衡 liveness 保持无鉴权，`/health/ready` 仅允许受限运维网络访问（由反向代理策略强制），不得泄漏依赖详情。部署文档给出该网络策略。新增静态审计测试，阻止 `app/` 的生产代码出现未经登记的 HTTP(S) 直连或非 Tencent WSS URL。

### 服务端结构化运行日志

新增 `runtime_log_events` 表，字段为：递增 `id`、可空 `user_id`、`level`、`category`、`message`、`details_json`、`request_url`、`duration_ms`、`status_code`、`exception_traceback`、`service_name`、`created_at`。`category` 固定为 `user_action`、`system`、`exception`、`third_party`、`strategy`；`level` 固定为 `DEBUG`、`INFO`、`WARN`、`ERROR`。URL 去除 query、authorization、token、key、sig 等敏感参数，异常堆栈和 JSON 详情也须脱敏。

`RuntimeLogService` 是唯一写入入口，提供：用户操作事件（登录、策略/设置保存、创建/确认/跳过下注）、worker/API 生命周期与 CPU/内存快照、异常记录（附格式化堆栈）、第三方代理请求的 URL、耗时、状态码及失败详情。第三方 HTTP 统一经过可注入的记录包装器，以便成功和异常路径都产生事件。worker 启停以及 API 生命周期记录系统事件。CPU/内存监控默认每 5 秒采样一次并写入服务级事件；采样失败本身记录 WARN，且不得停止 worker。

`GET /v1/runtime-logs` 需要有效 JWT，使用用户可见性规则：读取当前用户事件，加上不含其他用户数据的服务系统/第三方状态事件。参数为 `level`、`category`、`keyword`（最长 200 字符）、`start_at`、`end_at`、`before_id` 和 `limit`（1–100，默认 50）。结果按 `id DESC` 返回，含 `items`、`next_before_id`、`has_more`；关键字只匹配消息与已脱敏详情，不匹配或返回秘密。路由拒绝无效枚举、无效日期和倒置时间范围。

### 自动下注面板日志

`ServerApiClient.runtime_logs(filters)` 包装该接口并保留登录前拒绝行为。`AutoBetPanel` 的日志区域改为筛选栏（级别、开始/结束时间、关键字、刷新间隔）、轻量列表和“加载更多”按钮。默认级别为全部、时间为最近 24 小时、关键字为空、页大小为 50、刷新为 5 秒；刷新间隔可选关闭、5、10、30、60 秒。刷新定时器只在面板可见且服务器模式已认证时工作；筛选变化取消旧游标并重新加载首屏；手动“加载更多”使用 `next_before_id` 追加页面。新首屏渲染替换而非无限追加，单次最多 50 行，故长时运行不会卡顿。

本地自动下注 `InjectRecord` 仍以本地事件形式显示并标注来源；服务器模式下，服务端日志是权威来源。请求失败时保留已显示结果、展示简短 WARN 状态，并在下一周期重试；定时器、请求和 UI 写入均在 Qt 主线程协调，避免重入。日志视图不显示 `user_sig`、AI key、JWT、授权令牌或未脱敏 URL 参数。

### 折叠分组

增加可复用 `CollapsibleSection`：标题按钮控制同一个已经创建的内容容器的可见性，使用 `QParallelAnimationGroup` 动画其最大高度，并暴露 `expanded` 状态。它不会重新创建子控件、重新绑定信号或调用数据加载函数。初始化后记录各分组状态；用户手动切换时仅更新该状态。布局完成和窗口尺寸变化后调用现有 splitter/scroll-area 几何刷新，保证无重叠或延迟加载。

四个一级模块按以下归类，且均默认仅展开基础配置：

| 一级模块 | 基础配置（默认展开） | 高级配置（默认收起） | 操作（默认收起） |
| --- | --- | --- | --- |
| 线路选择 | 线路卡片、当前线路状态 | 线路刷新/代理状态 | 手动刷新或重试入口 |
| 账号与数据源 | 用户名、已解析数据源、状态 | 手动数据源路径 | 自动定位、浏览、使用数据源 |
| 屏蔽名单 | 当前群组、群组名单编辑 | 全局名单、汇总预览 | 保存/清空全局和群组规则 |
| 自动下注 | 策略、目标群组、玩法、金额、启动状态 | 赔率、封盘、AI/策略、概率与统计 | 启动/停止、确认/跳过、AI 历史、日志筛选/加载更多 |

为最小化现有 UI 改动，布局构建阶段先构造全部原控件，再将其放入三个持久内容容器；原属性名、信号与调用方保持不变。折叠/展开不得改变文本、勾选状态、当前下拉选择、运行状态、已加载历史、待确认订单或正在进行的刷新。

## 错误处理与安全

- 客户端在服务器模式下若服务端不可用，显示连接错误并停止非 Tencent 的直连回退；不能因降级而访问第三方。
- 服务器对所有入站参数实施长度、枚举、页大小、日期范围校验；路由级依赖执行认证、令牌撤销和用户隔离。
- 服务端出站请求限定在代码注册的来源，不接受客户端提供的任意 URL；记录 URL 使用脱敏和来源标签。
- 日志查询只返回当前用户可读事件；管理员跨用户查询若后续需要，必须是独立、审计过的管理员端点，不包含在本次普通用户接口中。

## 验收标准

1. `docs/api-interface-inventory.md` 覆盖所有 FastAPI 路由、桌面 HTTP/WSS 入口、worker 出站调用和诊断网络工具；每项都具备调用链、认证、校验、中转结论和测试证据。除被明确登记的 Tencent IM REST/WSS 外，生产客户端无第三方 HTTP(S)/WSS 直连。
2. 服务端运行日志覆盖登录、策略设置、下注创建/确认/跳过、API/worker 启停、CPU/内存快照、异常堆栈、第三方 URL/耗时/状态码；持久化记录不含凭据或秘密。
3. `/v1/runtime-logs` 正确执行 JWT、用户隔离、级别、时间、关键字和游标分页；无效筛选返回 422，跨用户事件不可读取。
4. 自动下注面板默认每 5 秒刷新，允许配置间隔；四种筛选和分页有效，刷新单页最多 50 项，不会因长日志全量渲染卡顿，且请求错误保留当前数据。
5. 四个一级模块都包含基础/高级/操作折叠分组，初始化仅基础展开；反复折叠/展开后控件实例、配置值、选中状态、运行状态和已加载数据保持不变，且 Qt UI 测试确认无几何异常。
6. 后端单元/集成测试、客户端 API/Qt 测试、静态网络审计测试与已有回归测试均通过；文档和部署说明匹配实际路由与反向代理限制。

## 测试策略

- 后端：日志服务、脱敏、CPU/内存采样、出站请求记录、日志查询筛选/游标/隔离、鉴权和输入校验；路由与 worker 生命周期集成测试。
- 客户端：`ServerApiClient` 日志协议与认证；面板的默认刷新、筛选重置、下一页追加、最大渲染量、错误保留和定时器生命周期。
- Qt：折叠容器默认状态、控件身份与值跨折叠保持、四模块分组归属、动画完成后大小约束。
- 审计：扫描生产客户端网络调用与 URL；仅 allowlist 的 `ServerApiClient` 和 Tencent IM 例外允许存在，诊断脚本必须出现在清单中并标为非生产入口。
