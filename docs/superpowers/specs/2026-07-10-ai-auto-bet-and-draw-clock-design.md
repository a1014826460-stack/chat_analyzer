# AI 自动下注与站点时钟设计

## 目标

修复断网或爬虫失败期间站点期号会因重复访问而错误递增的问题；在现有自动下注模块中增加 AI 策略，使用本地开奖缓存和既有历史抓取能力生成玩法建议，并通过现有 Web WSS 发送链路下注。

## 方案选择

不创建 MCP 服务。`HistoryFetcher`、`DrawResultStore` 和 `WsMessageSender` 已在同一进程中提供所需能力：本地缓存优先、外部历史抓取回填，以及不踢出现有客户端的 Web WSS 发送。再包装 MCP 会引入额外进程、协议和故障边界，当前没有实际收益。

## 站点本地时钟

每个站点仅使用其最后一次可靠 API 开奖计划来推导后续期号。可靠计划的锚点是 `current_period`、`start_time`、`next_time` 与站点固定间隔。

- 刷新或访问次数不改变期号。
- 仅当当前时间达到或越过 `next_time` 时，才本地推进一期；跨越多个完整间隔时逐期补齐。
- 首次启动从未得到可靠 API 数据时保留空期号和空倒计时，不做猜测。
- 解析、网络或爬虫失败返回回退数据时，必须从上述时间锚点推导，而非从每次调用时钟重新开始。
- API 恢复时只接受同一期或更新期；旧期响应不允许回退本地 UI。

## AI 策略配置

`StrategyConfig` 增加 `ai` 策略所需字段，随 `auto_bet` 保存至现有本地 `settings.json`：

- `ai_provider`：`openai_compatible` 或 `anthropic`。
- `ai_base_url`、`ai_model`、`ai_api_key`。
- `ai_history_count`：20 至 200，默认 50。
- `ai_require_confirmation`：每期确认开关。

API Key 在 UI 中采用密码隐藏输入，但按用户要求与其他自动下注设置一起保存到本地 JSON。

## AI 调用与数据流

启动自动下注时，仍创建 `DrawResultStore`。建议生成时调用 `get_recent_results(site, ai_history_count)`：它优先读本地 SQLite 缓存，缓存不足时通过 `HistoryFetcher` 和 `history_records.py` 获取历史开奖并回填。

每个站点、每期最多生成一份 AI 建议。客户端使用标准库 HTTP：

- OpenAI 兼容端点：`POST {base_url}/chat/completions`，Bearer 认证，请求 messages。
- Anthropic 端点：`POST {base_url}/v1/messages`，`x-api-key` 与 `anthropic-version` 请求头。

统一提示携带站点、最近开奖标签和全部 8 个合法玩法。模型必须仅输出 JSON：`{"play_type":"大|小|单|双|大单|小单|大双|小双","reason":"..."}`。客户端严格验证响应；HTTP 失败、超时、非 JSON、缺字段或非法玩法均不下注，只记录失败原因。

AI 仅选择玩法。下注金额沿用现有金额或倍投档位，赔率和结算也沿用已有运行时逻辑。AI 不受原有“功能”或玩法勾选限制。

## 确认与发送

- 未开启确认：建议校验通过后，服务向全部已选群生成相同玩法和金额，沿用 WSS、UIA 或后台窗口发送链路发送。
- 开启确认：服务保存当前期待确认建议并通知 UI；界面显示玩法、金额与理由，提供“确认下注”和“跳过本期”。
- 待确认建议到达封盘阈值则自动跳过；之后本期不再生成或发送。
- 同一 `site + period + group_id` 只发送一次。确认、跳过、超时、AI 失败和发送结果均写入运行日志。仅在实际发送阶段记录结算轮次。

## UI

自动下注策略列表增加“AI 下注”。选择它时：

- 显示 AI 提供商、Base URL、模型、API Key、历史期数和“每期下注前需确认”。
- 隐藏“功能”和玩法勾选；AI 可从全部八种玩法选择。保留金额、倍投、赔率、封盘时间、目标群、统计和日志。
- AI 待确认时显示建议摘要和确认、跳过按钮；未开启确认时不显示该区域。

## 测试

- 站点时钟：重复刷新不推进、到时只推进一次、跨越多个间隔补期、首次失败不推期。
- AI 客户端：OpenAI 兼容与 Anthropic 请求格式、严格响应解析、网络或响应失败。
- AI 服务：本地缓存读取、建议期内去重、确认发送、跳过、封盘超时、多目标群使用一致文本，以及仅 AI 确定玩法。
- 配置：AI 字段序列化与反序列化、面板配置与显示规则。

## 量化决策与反馈闭环

AI 每次分析前必须刷新当前站点的最新开奖记录，不能把“一次加载完成”的本地缓存长期作为最新数据。刷新成功后写入 `draw_results.db`；刷新失败时允许使用本地缓存，但日志必须说明数据新鲜度。

量化上下文固定包括：

- 最近 20 期和最近 50 期的 8 种玩法频率；
- 最新结果的连续出现次数；
- 最近 50 期的一阶玩法转移概率；
- 香农熵和最大类别集中度；
- AI 已结算下注的总体、短期方向命中率和精确命中率；
- 最近 AI 预测、实际结果及命中情况。

模型严格返回：

```json
{
  "action": "bet|skip",
  "play_type": "大|小|单|双|大单|小单|大双|小双",
  "confidence": 0,
  "quant_rationale": "量化依据",
  "reason": "简短结论"
}
```

`skip` 可以省略玩法。`bet` 的置信度低于用户阈值时由程序自动转为跳过；默认阈值为 65，允许设置 0 至 100。短期正确率窗口默认 20 条，允许设置 5 至 100。

所有建议都持久化到本地 SQLite，包括跳过、低置信度、失败、已发送和已结算记录。每条记录保存站点、预测期号、玩法、置信度、量化依据、理由、模型、历史快照、是否发送、实际结果和命中结果。

正确率只统计实际发送且已结算的 AI 下注：

- 方向命中：例如预测“大”，实际“大单”或“大双”均命中；
- 精确命中：预测玩法与完整开奖结果标签完全一致。

界面显示总体/短期双命中率、已结算数量、连中和连错，并提供最近 AI 历史记录查看。统计只作为下一期 Prompt 的反馈，不强制反向、加减金额或替换 AI 结论。
